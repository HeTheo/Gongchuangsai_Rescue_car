【2.1 先建 classes.txt —— 顺序绝对不能错】

  在 D:\工创赛\创新环节\ 里新建一个文本文件 classes.txt。
  一行一个类别，不带序号，不带空行。

  下面这 6 行是初赛的类别，如果创新环节的类别名/数量不一样，
  就换成你自己的（但这 6 行是最省事的方案，因为你不用改 New_v8.py

Black
Blue
Green
Orange
Safety_blue
Safety_red

  ★ 为什么不能错：
    labelImg 按这个文件的"行号"来编号，第 1 行 = 类别 0，第 2 行 = 类别 1。
    K230 端 New_v8.py 里写的是：

        labels = {0:'Black', 1:'Blue', 2:'Green',
                  3:'Orange', 4:'Safe_blue', 5:'Safe_red'}

    顺序错一位，模型学出来的"绿色"会是"蓝色"，上板全乱。

  ★ 如果创新环节要"新增类别"（比如多一个紫色危险物）：
    1) classes.txt 末尾追加一行，比如 Purple
    2) data.yaml 里 nc 从 6 改成 7，names 末尾加 'Purple'
    3) New_v8.py 里 labels 字典加 6:'Purple'
    4) New_v8.py 里再补两个常量，例如
         PURPLE_CLS = 6
       并决定它归到 DANGER_CLS 还是 RESCUE_PRIO 里
    ★ 第 3、4 步不做的话，板子上会把这个新类别当成"不存在"，检测框直接丢失。

  第 3 章  组装全新训练集（不用任何初赛旧数据）
########################################################################

【3.1 这次策略是"从零"，不是"在旧模型上补拍"】

  初赛补拍时的做法是：新数据 + 老数据混合 → 防止遗忘。
  这次不一样：创新环节的目标和初赛完全不是同一个东西，
  所以直接重建整个数据集，一次学全。

  推论（很重要）：

    ★ 新数据集必须自己就覆盖全部 6 个类别，一个都不能缺。
    ★ 不能出现"绿色只有 5 张"这种类别——模型根本学不会。
    ★ 不需要拷任何 My First Project.v3i.yolov11 里的东西。

  自检方法（3.5 节有脚本）：分完 train/valid 后，
  每个类别的实例数（Instances）都不能是 0，且最少那类不少于
  最多那类的 1/3。不满足就回去补拍。


【3.2 建全新的目录结构】

  ★ 用全新目录，绝对不要动初赛的 My First Project.v3i.yolov11

    $root = "D:\工创赛\ds_final"
    New-Item -ItemType Directory -Force -Path "$root\train\images","$root\train\labels","$root\valid\images","$root\valid\labels" | Out-Null
    Write-Host "目录已建好: $root"


【3.3 把标注好的图片按 8:2 自动分到 train / valid】

  先看标了多少张：

    (Get-ChildItem "D:\工创赛\创新环节" -Filter *.jpg -File | Measure-Object).Count

  然后跑这段（打乱后 8:2 拷贝，图片和同名 txt 成对）：

    $src  = "D:\工创赛\创新环节"
    $root = "D:\工创赛\ds_final"

    $imgs = Get-ChildItem $src -Filter *.jpg -File | Sort-Object { Get-Random }
    $cut  = [int]($imgs.Count * 0.8)
    $miss = 0

    for ($i = 0; $i -lt $imgs.Count; $i++) {
      $img = $imgs[$i]
      $lbl = Join-Path $img.DirectoryName ($img.BaseName + ".txt")
      if (-not (Test-Path $lbl)) { Write-Host "缺标签: $($img.Name)"; $miss++; continue }

      if ($i -lt $cut) { $d = "train" } else { $d = "valid" }

      Copy-Item $img.FullName "$root\$d\images\" -Force
      Copy-Item $lbl          "$root\$d\labels\" -Force
    }
    Write-Host "分配完成，缺标签 $miss 张"

  ★ 如果打印出"缺标签: xxx.jpg"，说明这张图在 labelImg 里没保存过标注。
    负样本也必须按 Ctrl+S 存出空 txt，否则会被算成"缺标签"跳过。

  ★ 负样本要保证 train 和 valid 里都有几张，别全分到一边。


【3.4 写 data.yaml】

  在 D:\工创赛\ds_final\ 里新建 data.yaml，内容如下（路径用 /）：

path: D:/工创赛/ds_final
train: train/images
val: valid/images
test:

nc: 6
names: ['Black', 'Blue', 'Green', 'Orange', 'Safety_blue', 'Safety_red']

  ★ names 的顺序必须和 classes.txt 完全一致（第 1 行 = 索引 0）。
    这是整个流程最容易崩的地方，详见第 2.1 节和 8.3 节。

  ★ 如果创新环节的类别定义和上面不一样（比如安全区不叫 Safety_blue），
    这里要和 classes.txt、New_v8.py 的 labels 三处同时改。
    nc 填类别个数。

  ★ 不要用老数据集那种 ../train/images 的写法，
    在新目录结构下会解析到错误位置。


【3.5 数据体检（★ 每次组装完都跑）】

  (1) 图片数 / 标签数要相等

    $r = "D:\工创赛\ds_final"
    foreach ($s in @("train","valid")) {
      $i = (Get-ChildItem "$r\$s\images" -File | Measure-Object).Count
      $l = (Get-ChildItem "$r\$s\labels" -Filter *.txt -File | Measure-Object).Count
      Write-Host "$s : images=$i  labels=$l"
    }

  必须 images == labels。不相等 → 有图片漏标或多出孤立 txt。

  (2) 负样本数量

    $z = (Get-ChildItem "D:\工创赛\ds_final\train\labels" -Filter *.txt -File |
          Where-Object { $_.Length -eq 0 } | Measure-Object).Count
    Write-Host "train 负样本(空txt) = $z 张"

  占全部图片 10%~20% 最合适。太少误检多，太多召回率掉。

  (3) ★ 最关键的一项：每个类别都要有样本，且数量均衡

    $names = @('Black','Blue','Green','Orange','Safety_blue','Safety_red')
    $dir = "D:\工创赛\ds_final\train\labels"

    $cls = @{}
    for ($k=0; $k -lt $names.Count; $k++) { $cls[$k] = 0 }

    Get-ChildItem $dir -Filter *.txt -File | ForEach-Object {
      Get-Content $_.FullName | ForEach-Object {
        if ($_ -match '^\s*(\d+)') {
          $k = [int]$matches[1]
          if ($cls.ContainsKey($k)) { $cls[$k]++ }
        }
      }
    }

    for ($k=0; $k -lt $names.Count; $k++) {
      Write-Host ("{0,-12} id={1}  实例数={2}" -f $names[$k], $k, $cls[$k])
    }

  判据：
    - 任何一类实例数 = 0        → 这个类根本没标，回去补拍补标
    - 最少那类 < 最多那类的 1/3  → 那个类学不好，回去补拍

  ★ 注意 PowerShell 里用 -Filter *.txt -File，不要用 -Include，
    -Include 在这个场景下返回空（踩过的坑）。

【4.1 训练命令】

  PowerShell：

    conda activate yolo
    cd D:\工创赛

    yolo detect train `
      model=D:\工创赛\yolo11n.pt `
      data=D:\工创赛\ds_final\data.yaml `
      epochs=60 `
      imgsz=320 `
      batch=4 `
      device=cpu `
      workers=0 `
      optimizer=AdamW `
      lr0=0.001 `
      lrf=0.01 `
      cache=False `
      patience=20 `
      project=D:\工创赛\runs\detect `
      name=train_final `
      exist_ok=False


【4.2 每个参数为什么必须这么写（都踩过坑）】

  ┌──────────────┬───────────────────────────────────────────────────────┐
  │ 参数          │ 说明                                                  │
  ├──────────────┼───────────────────────────────────────────────────────┤
  │ device=cpu    │ 强制 CPU。你的显卡只有 4G，训练必 OOM，别试了         │
  │ workers=0     │ ★ 必须 0。开 8 个进程会报 WinError 1455 页面文件太小    │
  │ batch=4       │ CPU 上内存占用小、稳。内存 16G 以上可以试 batch=8      │
  │ optimizer     │ ★ 必须显式写 AdamW。写 auto 会偷偷把 lr0 改成         │
  │   =AdamW      │   0.002 之类的默认值，lr0=0.001 就白设了              │
  │ lr0=0.001     │ 学习率。从预训练权重起步 0.001 就很稳，别用 0.01        │
  │ lrf=0.01      │ 末段学习率衰减到 lr0*0.01                             │
  │ imgsz=320     │ ★ 必须 320，和 K230 板端模型输入一致，不能改           │
  │ epochs=60     │ 500 张左右的数据，CPU 大概 60~120 分钟                │
  │ patience=20   │ 20 轮没提升就早停，省时间                             │
  │ cache=False   │ 别开。开了会吃好几个 G 内存                            │
  └──────────────┴───────────────────────────────────────────────────────┘

  ★ PowerShell 换行用反引号 ` ，不是 ^ （^ 是 cmd 的写法，会报错）

  ★ 不想换行就直接写成一行，去掉所有反引号，效果一样：

    yolo detect train model=D:\工创赛\yolo11n.pt data=D:\工创赛\ds_final\data.yaml epochs=60 imgsz=320 batch=4 device=cpu workers=0 optimizer=AdamW lr0=0.001 lrf=0.01 cache=False patience=20 project=D:\工创赛\runs\detect name=train_final


【4.3 为什么这次必须从 yolo11n.pt 开始，不能用初赛的 best.pt】

  初赛的 best.pt 你已经训好了，但创新环节不要拿它当起点，原因：

    ① 类别语义完全变了
       旧 best.pt 的 head 输出 6 个通道，学的是"初赛那套目标长什么样"。
       用它当前缀，模型会带着一堆关于旧目标的强先验，
       新目标反而学得慢、学不准。

    ② 旧模型对"安全区/出发区"的偏置会带过来

  所以这次只有一条路：

    model=D:\工创赛\yolo11n.pt        ← 永远是 COCO 预训练权重

########################################################################
  8.2  ★★★ 改 New_v8.py：只动 5 个地方，逻辑一行不改 ★★★
########################################################################

  原则：状态机、参数、函数体全部不动。
        只改文件最上面那块"配置区"，一共 5 个位置：

    ┌────┬──────────────────────────────────┬──────────────────┐
    │ #  │ 位置                              │ 改什么            │
    ├────┼──────────────────────────────────┼──────────────────┤
    │ 1  │ kmodel_path                       │ 模型文件路径      │
    │ 2  │ labels = {...}                    │ 类别名 + 索引     │

    │    │ SAFE_BLUE/SAFE_RED_CLS            │                  │
    │ 4  │ SAFE_USE                          │ 我方安全区是哪个  │
    │ 5  │ RESCUE_PRIO                       │ 救援目标优先级    │
    └────┴──────────────────────────────────┴──────────────────┘

  这三处（labels / 6 个常量 / data.yaml names）必须完全一致，
  它们是一个整体，改就必须一起改。


------------------------------------------------------------------
  改动 ① ：kmodel_path
------------------------------------------------------------------

  搜这一行：

    kmodel_path = "/sdcard/gongchuangsai_yolo11n_det_320_v3.kmodel"

  改成：

    kmodel_path = "/sdcard/gongchuangsai_yolo11n_det_320_final.kmodel"


------------------------------------------------------------------
  改动 ② ：labels 字典
------------------------------------------------------------------

  现在（初赛）：

    labels = {0: 'Black', 1: 'Blue', 2: 'Green', 3: 'Orange', 4: 'Safe_blue', 5: 'Safe_red'}

  改成和你 classes.txt / data.yaml 的 names 一模一样的顺序。

  ★ 格式要求：
      - 冒号左边是 0 开始的连续整数，不能跳号
      - 冒号右边用单引号括起来的字符串，不能有中文
      - 数量必须等于训练时的 nc
      - 顺序必须等于 classes.txt 的行顺序

  ★ 举例：如果创新环节的 6 个类别顺序变了，比如
      classes.txt 是：Orange / Black / Green / Blue / Safety_blue / Safety_red
    那 labels 就写成：

      labels = {0: 'Orange', 1: 'Black', 2: 'Green', 3: 'Blue', 4: 'Safety_blue', 5: 'Safety_red'}


------------------------------------------------------------------
  改动 ③ ：6 个类别常量
------------------------------------------------------------------

  紧跟 labels 下面，现在是：

    BLACK_CLS = 0
    BLUE_CLS  = 1        # 危险物（蓝色）
    GREEN_CLS = 2
    ORANGE_CLS = 3
    SAFE_BLUE_CLS = 4
    SAFE_RED_CLS  = 5

  ★★ 关键思路：常量名一个都不要改，只改右边的数字。

  因为后面几百行代码全是按这些"名字"来写的（比如
  `if d["cls"] == GREEN_CLS`）。你只要保证这些名字指向
  正确的索引，逻辑就自动跟着对。

  继续上面的例子（classes.txt = Orange/Black/Green/Blue/Safety_blue/Safety_red）：

    BLACK_CLS = 1
    BLUE_CLS  = 3        # 危险物
    GREEN_CLS = 2
    ORANGE_CLS = 0
    SAFE_BLUE_CLS = 4
    SAFE_RED_CLS  = 5

  ★ 如果创新环节的类别名和初赛完全一样（还是 Black/Blue/Green/
    Orange/Safety_blue/Safety_red，只是外观换了），那这里

  ★ 如果类别名变了（比如 Safety_blue 改叫 Zone_blue），
    那你必须把常量名也一起改，并且把文件后面所有引用这些
    常量的地方一起替换（用 VS Code 的 Ctrl+H 全局替换，
    输入的是旧常量名，不是字符串名）。


------------------------------------------------------------------
  改动 ④ ：SAFE_USE
------------------------------------------------------------------

  现在：

    # SAFE_USE     = SAFE_RED_CLS    # 填 SAFE_BLUE_CLS 或 SAFE_RED_CLS；None=两种都当安全区
    SAFE_USE     = SAFE_BLUE_CLS

  这一行决定"我方安全区是哪个颜色"。

  用法：
    - 我方抽到蓝色 → SAFE_USE = SAFE_BLUE_CLS
    - 我方抽到红色 → SAFE_USE = SAFE_RED_CLS

  ★ 比赛当天现场抽签决定，改这一个值就行，别的都不用动。
  ★ 这是唯一一个"赛前需要根据抽签现场改"的参数，
    提前把两行都写好、注释掉一行，现场只需换注释。


------------------------------------------------------------------
  改动 ⑤ ：RESCUE_PRIO
------------------------------------------------------------------

  现在：

    # 优先级：橙 > 黑 > 绿（值越大越优先）
    RESCUE_PRIO = {ORANGE_CLS: 3, BLACK_CLS: 2, GREEN_CLS: 1}

  这个字典有两个作用，两个都极其重要：

    (A) 定义"哪些类别算救援目标"
        parse_detections() 里：
          elif cls_id in RESCUE_PRIO:  dets.append(d)
        ★ 不在这个字典里的类别，会被静默丢弃，永远进不了 dets，
          表现就是"板上明明看到框了，但车完全不追"。

    (B) 定义"同距离时优先抓谁"
        pick_target() 里按 -RESCUE_PRIO[cls] 排序
        数值越大越优先。

  改法：
    - 先确认你所有的救援目标都在里面（几个目标就写几个 key）
    - 再按战术给优先级数字，比如
        RESCUE_PRIO = {ORANGE_CLS: 3, BLACK_CLS: 2, GREEN_CLS: 1}
    - 危险物（DANGER_CLS）不要写进来，它走 dangers 列表


------------------------------------------------------------------
  其它几个"角色"常量，改类别时要知道它们被谁用
------------------------------------------------------------------

  这些不用改，但换类别时必须确认它们指向的意义是对的：

  ┌───────────────┬──────────────────────────────────────────────┐
  │ 常量           │ 它在代码里承担的角色（改错了会出什么现象）      │
  ├───────────────┼──────────────────────────────────────────────┤
  │ DANGER_CLS     │ 危险物。框到它就判"不合格"→APART 分离。        │
  │ =BLUE_CLS      │ 改错 → 车会把危险物当目标抓                      │
  ├───────────────┼──────────────────────────────────────────────┤
  │ GREEN_CLS      │ ★ 最重要的角色："第一个必须送进去的目标"。      │
  │                │ ① pick_target 在 green_done=False 时只找它      │
  │                │ ② check_vote 首次框里必须有它                   │
  │                │ ③ has_green_in_safe 用它判断安全区左半有没有它   │
  │                │ ④ GO_SAFE phase5 用它决定 green_done            │
  │                │ ⑤ MULTI_GRAB_CLS 里它可配对搬                   │
  │                │ 改错 → 车永远"找不到绿"，一直绕圈不送            │
  ├───────────────┼──────────────────────────────────────────────┤
  │ ORANGE_CLS     │ 必须独占、并送安全区"右半区"的目标。            │
  │                │ ① check_vote：橙不能和别的混装                  │
  │                │ ② target_side()：橙 → 右转送，其它 → 左转送      │
  │                │ 改错 → 目标会被推进错误的一半                    │
  ├───────────────┼──────────────────────────────────────────────┤
  │ BLACK_CLS      │ 可以和绿配对一起搬（MULTI_GRAB_CLS）。          │
  │                │ 改错 → 不会合搬，效率降低，但不致命              │
  ├───────────────┼──────────────────────────────────────────────┤
  │ SAFE_BLUE_CLS  │ 两个安全区标记，一起进 SAFE_CLASSES。           │
  │ SAFE_RED_CLS   │ SAFE_USE 从这两个里选一个做"我方"                │
  └───────────────┴──────────────────────────────────────────────┘


------------------------------------------------------------------
  改完之后的 3 条自检（★ 必做）
------------------------------------------------------------------

  (1) 数量一致

        打开 New_v8.py，数一下 len(labels) 是多少。
        必须等于 data.yaml 里的 nc，也等于 classes.txt 的行数。

        然后被 except 抓住 → state 被重置成 SEARCH → 看起来像"乱跑"。

  ── 2. 组数据集（全新，不拷任何旧数据）────────────────────────
  $root = "D:\工创赛\ds_final"
  New-Item -ItemType Directory -Force -Path "$root\train\images","$root\train\labels","$root\valid\images","$root\valid\labels" | Out-Null

  $src  = "D:\工创赛\创新环节"
  $imgs = Get-ChildItem $src -Filter *.jpg -File | Sort-Object { Get-Random }
  $cut  = [int]($imgs.Count * 0.8)
  for ($i = 0; $i -lt $imgs.Count; $i++) {
    $img = $imgs[$i]
    $lbl = Join-Path $img.DirectoryName ($img.BaseName + ".txt")
    if (-not (Test-Path $lbl)) { Write-Host "缺标签: $($img.Name)"; continue }
    if ($i -lt $cut) { $d = "train" } else { $d = "valid" }
    Copy-Item $img.FullName "$root\$d\images\" -Force
    Copy-Item $lbl          "$root\$d\labels\" -Force
  }

  然后手写 D:\工创赛\ds_final\data.yaml：

    path: D:/工创赛/ds_final
    train: train/images
    val: valid/images
    test:

    nc: 6
    names: ['Black', 'Blue', 'Green', 'Orange', 'Safety_blue', 'Safety_red']

  ── 3. 体检（数量和每类实例数）──────────────────────────────

========================================================================
  最后四条硬提醒
========================================================================

  1) 顺序一致性是这个项目最容易崩的地方：
       classes.txt  ←→  data.yaml 的 names  ←→  New_v8.py 的 labels
     这三处必须一字不差、一行不差。改任何一处都要同时改另外两处。

  2) 这次是从零训，所以数据集必须自己就"完整"：
       - 6 个类别每类都要有样本，最少那类不少于最多那类的 1/3
       - 远距离小框必须专门拍（误检重灾区）
       - 不拷任何初赛旧数据，也不要用初赛的 best.pt 当起点

  3) 负样本不要省：
       出发区、空场地、地面纹理、半截安全区、杂物，
       合计要占全部图片的 10%~20%。
       少了 → 出发区被误检成安全区，这是初赛踩过的坑。

  4) 标定图必须是真实场地照片：
       nncase 量化对着什么图统计，上板就偏成什么样。
